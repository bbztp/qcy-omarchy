# Control-panel JSON schema (`product/findControlPanels`)

Extraction only: nothing here was run on hardware. Sources:

  one `findControlPanels` reply per vendorId; `n70_findControlPanels.json`, the live N70 reply),
- the app parser the vendor app (`analyseJSON`, the `switch` on `type`),
  the vendor app, the vendor app, the vendor app,
- `WEB_API.md`, `PROTOCOL.md` and the embedded snapshot `internal/qcycore/models/models.json` (+ `models.go`).

Per-model data (221 vendorIds, functions declared, values and limits, snapshot coverage):
[`panels-by-model.json`](panels-by-model.json). It is generated by a script from the same 221
files, so every count below can be recomputed from it.

Evidence labels used below: **data** = seen in the 221 JSONs; **parser** = documented parser behaviour; **PROTOCOL** = already in `PROTOCOL.md` (some of it verified on the N70 there); **inferred** =
my reading, not confirmed.

## 1. Corpus

| | count |
|---|---|
| vendorIds in `panels/` | 221 |
| with a panel (`data.controlPanel.layouts` present) | 191 |
| without (`data: null`, reply `success`) | 30 (23875 CT03, 23885 HT27, 16823, 18812, 18814, 19220, 6577, 512, and 22 watches 355xx-518xx) |
| distinct numeric `type` values, top level | 31 |
| distinct numeric `type` values, inside type-4 `items[]` | 11 |
| distinct `type` values overall (the two sets overlap on 1, 2, 3, 4) | 38 |
| layouts with no `type` at all (ignored by the parser) | 2 models (4579 C1, 19782 TWS HT07) |

Values of the same field come as JSON numbers in some replies and as strings in others
(`"type": "200"`, `"cmdid": "42"`, `"eventID": "1"`, `"jump": "1"`). The app reads them with
`optInt`, so both work; a Go decoder has to accept both (`json.Number`-like).

The server reply for a vendorId depends on the `firmwareVersion` request field only through
`firmwareversionGte/Lte`: all 191 stored panels were fetched with `0.0.0` and are the
generic one. For the N70 the stored reply with `3.0.13` differs from `panels/23872.json` only in
`data.firmwareVersions` (checked key by key), so firmware did not change the layout.

## 2. Envelope

```
{ code, success, msg, time,
  data: { firmwareVersions, firmwareversionGte, firmwareversionLte,
          controlPanel: { layouts: [ <layout>, ... ] } } }
```

`data` is `null` for products without a panel (watches, a few earbuds). `firmwareversionLte` is
`999.999.999` for 172 of the 191 panels; the rest are a bounded range (for example the QCY QT22
panel is `0.0.0`..`1.6.3`): the server serves a different panel per firmware window.

A `layout` is one UI block. The parser (`analyseJSON`, lines 302-486) walks `layouts` in order and
switches on `layout.type`; unknown types are silently skipped. The panel is therefore an unordered
**set of independent function declarations**, not a tree.

## 3. Fields

| field | where | meaning | app behaviour |
|---|---|---|---|
| `type` | layout, item | function kind (table in section 4). Number or numeric string | selects the UI widget and the frame builder |
| `name` / `title` | layout / item | label, localised by the server (`lang` header) | shown; the parser copies `title` to `name` when `name` is absent |
| `info` | layout | HTML snippet (`<font color=...>`) with the help text | shown in the "i" popover |
| `id` | layout, item | list order / row id (1, 3, 101, 102, 103, 1000, 1001...) | only used as a row key; not a protocol value |
| `jump` | layout, item | `1` = put the row on the "More" page, `0` = main settings list | `moreSingleJson` vs `otherSingleJson`. Not a protocol value |
| `cmdid` | layout, item | **BLE command id** of the frame `FF <len> <cmdid> <paramLen> <params>` (PROTOCOL.md "Packet format"). `cmdid 36` is `0x24` multipoint, `35` is `0x23` LDAC, `42` is `0x2A` wind noise, etc. | added to `readCmdIndexList`: the app issues one `FF 03 FE 01 <cmdid>` query per entry at connect time |
| `hasValue` | layout | the function has a readable value | read by no code path found in the parser (grep of `"hasValue"` finds nothing): informative only |
| `repeat` | type 102 | `50000` or `65000` | **unknown**. Not read anywhere in the app code searched. Looks like a UI/limit constant, not a frame field. Do not use |
| `msg`, `msg_ios`, `msg_android` | item, layout | confirmation or warning text shown before applying ("Turning on LDAC will restart the device") | the platform variant wins when present. **Useful as a restart-warning source** |
| `alert` | item (1 model) | extra popup flag | shown with the toggle |
| `character` | item, key group, EQ | GATT characteristic UUID the value is written to. Seen: `00001001-...` (settings v2, `FF..` frames), `0000000B` (EQ), `0000000D` (key remap v2), `0000000F` (settings v1, 1-byte), `00000009` (language), `0000000A`/`0000000E` (reset v1), `00000001`..`0000000A` (legacy per-gesture key chars) | choose the write target. | `cmd` | item (type 3/100) | raw frame in hex string, e.g. `FF020100` | written as is to `character` after the confirm dialog |
| `sub_items[]` | item (200-206, 2) | `{cmd, boolVal}` pairs: the **full frame** to send for on (`boolVal:true`) and off. Example LDAC `FF03230101` / `FF03230102` | toggle: sends `cmd` of the chosen branch |
| `manufacturers` | item type 1 | OTA vendor selector (9, 10, 11 seen); stored as `otaType` | passed to the OTA activity as `OTAType` |
| `position` | item type 3/100 | list position hint (5 items) | ordering only |
| `languages` | type 1001 | comma list of UI locales in which the row is shown (`"zh"` in 40 of 41) | **the row is hidden unless the phone locale is in the list** (`Locale.getDefault().getLanguage()`), though the earbuds support the command regardless |
| `itemKey`, `itemName` | type 1001 | parallel arrays: values (hex of 4 ASCII bytes, e.g. `57513030` = `WQ00`) and labels | selection list; the key bytes are the value written |
| `itemName` (object) | types 103, 1000 | map `value -> label`: keys are hex of the byte(s) written (`0500` = 5 min as 2-byte little-endian, `FFFF` never) for 1000; decimal levels (`4`,`6`,`8`,`10`) for 103; hex bytes (`26`,`2D`,`34`) for touch sensitivity | selection list |

`type`; "item" = a `type` inside a `type: 4` layout's `items[]`. Frame column: `PROTOCOL` = in
`PROTOCOL.md`; `inferred` = same cmdid-as-frame-id rule, no hardware check; `-` = no frame.

## 5. How the main blocks work

### Key remapping (types 1, 10, 14)

| | type 10 (N70 family) | type 14 | type 1 (legacy) |
|---|---|---|---|
| structure | `music.event[]` each `{name, left{eventID,list,defaultFun,default}, right{...}}`; optional `voice.event[]` (30 models), `sdMode` (1) | `buttons[{keyName, events[{eventID, list, defaultFun}]}]` | `left/right.{single,double,three}_click`, `long_press`: `{name, music(default), list, character}` |
| write | `[eventID, action]` to `0000000D` | same | 1 byte (`action` hex) to `00000001`..`0000000A` |
| event ids | 1/2 touch L/R, 3/4 double, 5/6 triple, 9/10 long (N70) | 17-32, 769, 1281, 1793-1796 | by characteristic |

Action ids seen in type 10 (all models): 0 not work, 1 play/pause, 2 previous, 3 next, 4 voice
assistant, 5 volume up, 6 volume down, 7 game mode / low latency, 11 ANC mode (N70: 0-7 and 11),
14 focus mode (2 models), 15 spatial sound (12 lists), 81-86 game EQ presets (6 lists). Labels vary
by model ("Play/pause" vs "Playback/pause"); the id is what matters. Legacy type 1 adds `08` take
picture, `0A`/`0B` ANC.

### ANC (types 9, 6, 11)

Type 9: `modes[]` -> `{name, startcmdid, endcmdid, defaultcmd, viewtype, items?}`. The packed value
is `(mode<<16)|(subScene<<8)|level`:

| group | start | end | default | meaning (N70 and 46 more models) |
|---|---|---|---|---|
| Noise canceling | 65792 (`0x010100`) | 131071 | 66816 | mode 1; items: Adaptive 66816 (`0x010500`), Indoor 65792-65794, Commuting 66048-66050, Noisy 66304-66306, Anti-wind 66560 (`0x010400`) |
| Normal | 131072 (`0x020000`) | 131072 | 131072 | mode 2 |
| Transparency | 196864-196870 (`0x030100`..`0x030106`) or 196868 | | 196868 | mode 3; `voicecmdid 196864` on N70 (voice enhance); `viewtype 2` = slider with levels 0-6 |

Four models use an older single-byte encoding (65-159, 160-166, 2): not the N70 family.
`toastMsg/toastTip` (6 models) are wear-state warnings; `envAdaptation` (11 modes) adds a read of
`0x32`.

### EQ (types 2, 23)

| field | N70 (23872, 23877) | corpus |
|---|---|---|
| `count` | 10 | 10 in 183 models, 5 in 7 (the `freq` string is `31,62,...,1k,...` in 96 models, with `1000,2000` in 54, `32,64,...` in 16) |

### Toggles and selectors

All toggles are `FF 03 <cmdid> 01 <v>` frames declared literally in `sub_items`; the value
selectors (types 102, 103, 104, 1000, 1001) declare the allowed values as `itemName` keys. Their
cmdid -> function is in `panels-by-model.json` (`func`, `cmdid`, `values`) and summarised in section 7.

## 6. N70 (23872, 23877) against the rest

- `panels/23872.json` and `panels/23877.json` have **identical `data`** (checked with `==`), and
  23872 equals the live `n70_findControlPanels.json` except `firmwareVersions` (`0.0.0` vs `3.0.13`).
  `firmwareversionGte/Lte` are `0.0.0` / `999.999.999`: one panel for every firmware.
- 13 layouts, 20 functions: keys (type 10), ANC scenes (9), EQ with `individuation_eq` (2),
  balance (8), find (3), tone language (1001), rename (101), timing power-off (102), fit (110),
  wear + sensitivity (104, cmd 44 + 72), beep volume (103, cmd 29), auto power off (1000, cmd 31),
  and the type-4 group: game mode (203, cmd 9), wind noise (200, cmd 42), sleeping mode (200, cmd
  16), LDAC (200, cmd 35), dual device (200, cmd 36), firmware update, reset default (type 3),
  reset factory (type 100).
- **Same function set as the N70**: 23874 and 23879 (MeloBuds N60), 23880 and 23881 (N70i),
  23883 (HT19 MeloBuds DUAL BT6). 23873 and 23878 (AilyBuds E50) have it plus spatial audio
  (item 200, cmd 45). 19790 (HT08 MeloBuds Pro Plus) has it minus fit detection and wind noise.
- What the N70 has that most models lack (share of the other 189 panels): wear detection 9,
  wind-noise toggle 16, fit detection 18, LDAC 30, tone switch 39, `individuation_eq` 6, and the
  scene ANC with adaptive + 7-level transparency (about 49).
- What many other models have that the N70 does **not** declare: in-ear sensor toggle (22 models),
  adaptive volume (8, cmd 64), dynamic EQ (10, cmd 39), spatial audio switch (8, cmd 45/91), touch
  sensitivity (8, cmd 51), mode switching (7), AI scene ANC (5, cmd 84), light effect (5),
  head control (2), clear-pairing item (20), TWS team-up (4, cmd 52), eco mode (3, cmd 83).
  (The N70 EQ list does carry an effect named "Spatial sound effects", id 10, in 35 models; this

## 8. What `models.json` already covers, and what it lacks

Coverage per declared function (counted per function entry across the 191 panels, see
`modelsJson` in `panels-by-model.json`):

| status | functions |
|---|---|
| **structured** (own typed field, `Panel.*`) | EQ (`eq`, 190), find, balance, keys (type 1/10/14, `Panel.Keys`), timing power-off type 102 (`autoOff`), beep (`beep`), wear + sensitivity (`wear`), fit (`fit`), ANC scenes type 9 (`anc`) |
| **stub** (`Panel.Other`: only `{type, name, cmdId}`, with `type` 4 for every item) | auto power off type 1000 / cmd 31 (63 models; `autoOff` is filled only from type 102), firmware, rename, reset default/factory/clear pairing, game, sleep, multipoint, LDAC, wind noise, dynamic EQ, spatial, in-ear, adaptive volume, touch sensitivity, mode switching, tone switch, ANC type 6/11, light, AI ANC, head control, volume, focus, alarm... |
| **missing** | type 13 `cmdIndexs` (4 models) |

Fields the snapshot does **not** carry (every item below is in the server JSON):

1. **Toggle frames**: `sub_items[].cmd` on/off and `character` for all type 200-206 items. The
   snapshot has the cmdId only, so the on/off value (`01/02`, wind noise off `00`) must be
   hard-coded.
2. **Raw command items**: `cmd` hex (`FF020100`, `FF020200`, `FF020300`), `character` and the
   confirm `msg` for reset / clear pairing / factory reset.
3. **Restart and warning texts**: `msg`, `msg_ios`, `msg_android`, `alert`, `rebootTip`,
   `alarmMsg`, `confTip`, `toastMsg`; they are the only server-side statement of "this restarts
   the earbuds".
4. **ANC extras**: `viewtype`, `voicecmdid` (transparency voice, 19 modes), `envAdaptation`,
   `envName`, `ancInvert`, `hidePop`, `noSpaceTip`, `describe`, mode `touchDisable`, `toastTip`.
   Only `name/start/end/default` survive.
5. **EQ**: `count`, the string `q`/`iitType` of the panel, `volumelevel`, `character`,
   `supportMaxCount`, `vals`, `onlyTws`, `individuation.soundDB` (the hearing-test baseline), `aux_eq`
   (`Individuation` only keeps `bands`), per-effect `alarmMsg`.
6. **Keys**: `defaultFun` / `default` (factory action per event), `voice` event set (30 models),
   `sdMode`, the `character` of the legacy per-gesture writes, `keyName` of type 14 (only
   `name/eventID/actions`).
7. **Selector values**: tone switch `itemKey` (the 4 ASCII bytes) and `languages`; touch
   sensitivity / mode switching option bytes; the auto power off options (type 1000 `itemName`/`subItem`:
   `0500`, `0A00`, `1E00`, `3C00`, `FFFF` as 2-byte little-endian minutes; `AutoOff` is filled from type 102 only (`cmdId` 20 + `repeat`); the type 1000 / cmd 31 row survives
   only as `Other{type:1000, cmdId:31}`); spatial audio `subItem` index.
8. **Misc blocks**: type 105 `effects`, type 115 `configs/sceneList/actionList`, type 114
   `actions`, type 116 `subItem`, type 104 `subTitle/valueTitle/ancMsg`, type 3 `latitude/longitude`,
   type 101 `maxLength`, `manufacturers` (OTA type), `jump`, `position`, layout `id`.
9. **Firmware window**: kept (`firmware.gte/lte`), but only the generic (`0.0.0`) panel exists;
   firmware-specific panels (for example QT22 `0.0.0`..`1.6.3`) are not in the snapshot.
10. **30 products with `data: null`** are stored as `panel: null`, which matches.

Consequences for the N70 support: wear detection, wind noise, sleep mode, LDAC, game mode,
multipoint are declared by the server for 23872/23877, so the capability set the code can
show is exactly the 20 functions in section 6; spatial audio (cmd 45), in-ear sensor (cmd 6),
adaptive volume (64) and dynamic EQ (39) are **not** declared for the N70 even though the same
cmd ids exist on other models.
